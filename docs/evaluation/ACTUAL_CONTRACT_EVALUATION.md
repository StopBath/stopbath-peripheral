## 4.1 The devices' flag sets

### Flipper, device build

Source: the compile line `ufbt` actually issued for `protocol/remote_protocol.c`,
read from `stopbath-flipper/.vscode/compile_commands.json` (regenerated by
every `ufbt` run), and `.ufbt/current/sdk_headers/sdk.opts`, whose `cc_args`
`ufbt` installs as `CFLAGS_APP` (`.ufbt/current/scripts/ufbt/site_tools/ufbt_state.py:91`,
`.ufbt/current/scripts/ufbt/SConstruct:213`). The two agree.

Warning flags: `-Wall -Wextra -Werror -Wno-error=deprecated-declarations
-Wno-address-of-packed-member -Wredundant-decls -Wdouble-promotion -Wundef`.

Code generation flags: `-mcpu=cortex-m4 -mfloat-abi=hard -mfpu=fpv4-sp-d16
-mthumb -fdata-sections -ffunction-sections -fsingle-precision-constant
-fno-math-errno -g -Os -mword-relocations -mlong-calls -fno-common -nostdlib`,
plus the SDK's `-D` set including `-DFW_ORIGIN_Unleashed -DFURI_NDEBUG -DNDEBUG`
and the manifest's `-DFAP_VERSION`.

Observed, and a correction to the Flipper evaluation log: `-std=gnu2x` and
`-Wstrict-prototypes` are NOT on the device compile line. The Flipper log 4.1
took them from `site_scons/cc.scons` in the firmware tree, but the deployed
SDK's `sdk.opts` does not carry them and `ufbt` adds nothing of its own. The
Flipper log's line "the deployed `sdk.opts` carries the compiler flags 4.1
recorded" is therefore wrong on those two flags. The device compiles under the
compiler's default standard, `__STDC_VERSION__ 201710L` (gnu17) for gcc 12.3.
Both host Makefiles add `-std=gnu2x -Wstrict-prototypes` anyway, which is
stricter than the device, so nothing built today is affected; it matters only
for the claim the `shared/` job makes.

Observed: `-fshort-enums` is not passed either. It is the ABI default of
`arm-none-eabi-gcc`. Probe (`enum small { A_VALUE = 1 }; int enum_size =
sizeof(enum small);`, compiled `-S` with the Flipper toolchain): `.word 1`
by default, `.word 4` with `-fno-short-enums`; host gcc 15.2.0: `.long 4`.
So the Flipper log's finding stands (an enum is one byte on the device) and
the peripheral spec's 4.5 GUIDANCE, host `gcc` plus `-fshort-enums` as the
cheap approximation, is the right one. Note for anyone repeating the probe on
Windows: the toolchain's `cc1.exe` exits `0xC0000135` (a DLL not found) with
no message unless the toolchain's `bin` directory is on `PATH`; `ufbt` puts it
there itself.

### Pico, device build

Source: `stopbath-pico/firmware/CMakeLists.txt` (`BASE_WARNINGS`,
`PROJECT_WARNINGS`, `VENDORED_WARNINGS`) and the compile line ninja issued for
`protocol/remote_protocol.c`, read from `stopbath-pico/build/firmware/build.ninja`.

Warning flags for this project's own sources: `-Wall -Wextra -Werror
-Wstrict-prototypes -Wredundant-decls -Wdouble-promotion -Wundef -Wshadow
-Wconversion`. Vendored sources (`lib/waveshare`, `lib/qrcodegen`): the same
without `-Wshadow -Wconversion`.

Code generation flags, all from pico-sdk for `PICO_BOARD=pico2_w`:
`-mcpu=cortex-m33 -mthumb -march=armv8-m.main+fp+dsp -mcmse -mfloat-abi=softfp
-ftls-model=local-exec -g -O3 -DNDEBUG -fno-math-errno -ffunction-sections
-fdata-sections`. No `-std`; the compiler default for gcc 15.2 is
`__STDC_VERSION__ 202311L` (gnu23). Same enum probe with the Pico toolchain:
`.word 1`, so both devices are short enum targets.

### Both, host build

Source: `stopbath-flipper/Makefile` and `stopbath-pico/Makefile`. Identical
flag sets: `-std=gnu2x -Wall -Wextra -Werror -Wstrict-prototypes
-Wredundant-decls -Wdouble-promotion -Wundef` as the base, `-Wshadow
-Wconversion` added for project sources, `-O1 -g`, vendored code held to the
base set. Sanitiser build adds `-fsanitize=address,undefined
-fno-omit-frame-pointer -fno-sanitize-recover=all`. Every test binary links
with `-Wl,--wrap=malloc,--wrap=calloc,--wrap=realloc,--wrap=free` so
`tests/test_support.h` can prove a path did not allocate.

### Union and difference

| Flag | Flipper device | Pico device | Host (both) |
|---|---|---|---|
| `-Wall -Wextra -Werror -Wredundant-decls -Wdouble-promotion -Wundef` | yes | yes | yes |
| `-Wstrict-prototypes` | no | yes | yes |
| `-Wshadow -Wconversion` (project sources) | no | yes | yes |
| `-Wno-error=deprecated-declarations -Wno-address-of-packed-member` | yes | no | no |
| `-std=gnu2x` | no (gnu17 default) | no (gnu23 default) | yes |
| short enums | yes (ABI default) | yes (ABI default) | no |
| optimisation | `-Os` | `-O3` | `-O1` |
| sanitisers, heap wrapping | no | no | yes |

Conclusion for the `shared/` continuous integration job: the union of warning
flags is the host set (the host set already contains every warning flag either
device enables), so one host compile under the host set plus `-fshort-enums`
covers the warning surface of both devices, and the two device jobs remain the
proof under the real toolchains, as the spec's 4.5 says. The only warning flag
a device has that the host set lacks is a demotion (`-Wno-error=...`), which
cannot make the host build miss anything. `-O3` against `-Os` against `-O1`
can surface different warnings (`-Wmaybe-uninitialized` in particular);
recorded as a residual, covered by the device jobs.

## 4.2 The devices' build entry points against a sibling directory

### The Flipper's manifest and `fap_private_libs`, read from source

`.ufbt/current/scripts/fbt_tools/fbt_extapps.py` at the deployed SDK:

- `_setup_app_env` (line 65) mounts the application directory as a SCons
  `VariantDir` at `EXT_APPS_WORK_DIR/<appid>` with `duplicate=False`; the
  application directory itself is mounted at `#/app/` as a SCons repository
  (`SConstruct:220-222`). Everything the manifest names is resolved under
  that mount.
- `_build_private_lib` (line 102) takes its sources from
  `<work dir>/lib/<lib name>` and nowhere else; `sources` entries are globbed
  recursively from there (`GlobRecursive` in `sconsrecursiveglob.py`), or,
  for an entry with no glob characters, taken as `node.File(pattern)`.
- `_build_app` (line 151) gathers `sources` with `GatherSources`, which
  applies the same rule and always excludes `lib`.
- The manifest is loaded by `fbt/appmanifest.py:179` `load_manifest`, which
  runs the file with a bare `exec(...)` inside that function, so the manifest
  sees that module's globals (`os` among them) and that function's locals
  (`app_manifest_path` among them). This is an implementation detail, not a
  documented interface.

## 4.5 Continuous integration mechanics

Read from `stopbath-flipper/.github/workflows/ci.yml` and
`stopbath-pico/.github/workflows/ci.yml`:

- Both run on `ubuntu-latest` with `actions/checkout@v4`,
  `actions/setup-python@v5` (3.12) for the scans, and plain `gcc --version`,
  `make test`, `make test-sanitise`, `make fuzz-sanitise FUZZ_ITERATIONS=200000`,
  `make peer` for the host jobs with nothing installed. That both are green
  today is the evidence that the runner image provides `gcc`, `make`, Python 3
  and the sanitiser runtimes; nothing more can be verified from this machine.
- The Flipper's device job: `pip install "ufbt==0.2.6"`, `ufbt update
  --hw-target f7 --url "$UNLEASHED_SDK_URL"`, `ufbt`, then uploads
  `dist/stopbath_remote.fap`. The URL is pinned in the workflow's `env`.
- The Pico's device job: `apt-get install cmake ninja-build`, then the same
  two scripts the development machine runs, `bash scripts/setup_toolchain.sh`
  (downloads the Arm toolchain, verifies the sha256, clones pico-sdk at the
  pinned tag) and `bash scripts/build_firmware.sh`, then uploads `dist/*.uf2`.
- Path filtering: GitHub Actions applies `on.<event>.paths` to a whole
  workflow file, not to a job. So "a change under `pico/` alone does not build
  the FAP" is expressed either as three workflow files (`ci-shared.yml`,
  `ci-flipper.yml`, `ci-pico.yml`), each with its own `paths:` list, where the
  device files list `shared/**` as well as their own directory, or as one
  workflow with a change detection job (a third party action, or a `git diff
  --name-only` step feeding job `if:` conditions). The three file form needs
  no dependency and is the one the spec's Part 3 tree (`ci.yml`, "path
  filtered") is best read as; recorded for `SE1`, no decision needed unless
  the author wants one file.
- Each device's job runs its `make` from inside its directory
  (`working-directory: flipper` and `pico`), and the `shared/` job runs
  `shared/Makefile` from `shared/`. The typography scan runs once, from the
  root.
